# Sprint 2 — Project Planning & Requirement Analysis

## Aim
To define the project requirements, stakeholders, scope, functional requirements, and non-functional requirements for the Library Management System.

## Project Information
- Project Title: Library Management System
- Domain: Education
- Technology Stack: MERN Stack
- Application Type: Web Application

## Problem Statement
Libraries need an organized system to manage books, members, borrowing, returns, and fines. Manual processes can make it difficult to track book availability, member records, borrowing history, and overdue fines. The Library Management System provides a centralized platform for these activities.

## Objective
To develop a web-based Library Management System that helps administrators and librarians manage books, members, borrowing, returns, fines, search, and reports efficiently.

## Stakeholders
1. Administrator
2. Librarian
3. Student
4. Teacher
5. Library Member

## Project Scope
The system will include:
- Login and authentication
- Dashboard
- Book management
- Member management
- Book search and availability
- Book issue/borrowing
- Book return
- Fine calculation
- Reports

## Functional Requirements
1. User Registration
2. User Login
3. Book Management
4. Member Management
5. Book Search
6. Book Issue
7. Book Return
8. Fine Calculation
9. Report Generation
10. User Management

## Non-Functional Requirements
- Performance
- Security
- Reliability
- Usability
- Scalability
- Maintainability
- Portability
- Backup and Recovery
- Compatibility

## Core Modules
- Authentication & User Management
- Book Management
- Member Management
- Book Borrowing
- Book Return
- Fine Management
- Search & Filter
- Reports & Analytics
- Dashboard

## Excluded Features
- Mobile application
- AI-based book recommendation
- Online payment gateway
- Third-party integrations
- E-book reading

## Result
The project requirements, stakeholders, scope, functional requirements, non-functional requirements, core modules, and excluded features were identified and documented for the next development sprints.
